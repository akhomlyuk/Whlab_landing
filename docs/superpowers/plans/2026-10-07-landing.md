# Визитка whlab.ru — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Заменить слово `temporary` на визитку: кто я, чем занимаюсь, где найти — одним файлом `index.html` плюс стили, без сборки.

**Architecture:** Чистая статика в приватном репозитории `akhomlyuk/Whlab_landing`. Сервер тянет код `git merge --ff-only` в `/srv/landing` и отдаёт nginx, который уже настроен. Вся разметка в HTML: страница обязана читаться без JS. Один слой оформления — `css/style.css` поверх `css/tokens.css`, токены взяты из `ctf-catalog` по назначению, а не скопированы пачкой.

**Tech Stack:** статический HTML, CSS с кастомными свойствами, ~40 строк JS на инлайн-скрипт переключения темы. Проверки — `tools/verify.py` на голом Python, без зависимостей.

**Spec:** `docs/superpowers/specs/2026-10-07-landing-design.md`

## О границах этого плана

План несёт то, что невозможно вывести: точные значения токенов, точные тексты, точные URL и точные проверки. Правила раскладки и визуальный слой CSS исполнителю пишутся сам по специ, разделам 3, 5 и 6 — это его работа, и дублировать тут триста строк вёрстки значит сделать план нечитаемым, а не точным.

## Global Constraints

- **Сборки нет.** Ни бандлера, ни препроцессоров, ни npm. `git pull` — и всё.
- **Никаких магических `rem`.** Отступы только из шкалы `--space-1…--space-8`.
- **Имя везде `Exited3n`** — слитно, с цифрой `3`. Не `ExIT & EDEN`, не `ExITEDEN`.
- **Вордмарк — текстом, не картинкой.** `static/exited3n_avatar.png` не используется вообще.
- **Тёмная тема — референсная**, значения живут в `:root`. Светлая — `[data-theme='light']`, то же дерево токенов, другие значения.
- **Ключ темы в `localStorage` — `whlab-theme`**, не `it-movies-theme`: настройки разных доменов не должны перетирать друг друга.
- **Три состояния темы:** `auto` (атрибута нет), `light`, `dark`.
- **`meta[name="theme-color"]` обновляется при смене темы** — иначе скроллбар и нативные контролы остаются в теме ОС.
- **Весь контент в HTML.** JS только переключает тему; выключенный JS не должен оставлять пустую страницу.
- **Сервер — `git merge --ff-only`,** никаких merge-коммитов на сервере.

## Review Focus

1. **Тема применяется после первой отрисовки.** Инлайн-скрипт в `<head>` обязан отработать синхронно до отрисовки `<body>`. Если он в конце файла или в модуле, пользователь видит вспышку светлой темы на тёмном домене — ровно то, что этот приём и существует чтобы предотвратить. Проверяется в Task 3.
2. **`var(--токен)` ссылается на несуществующий токен.** В `IT_movies` из-за этого однажды потерялся `--accent-text`, и молча сломалось всё, что на него опиралось. Опечатка в имени не падает, а тихо рисует наследование. Проверяется в Task 1 на каждом `var(--*)` из `style.css`.
3. **Внешняя ссылка открывается без `rel="noopener"`** — страница, открытая в новой вкладке, получает `window.opener` и может увести окно на свой домен. Все внешние ссылки — в новой вкладке. Проверяется в Task 2.
4. **Вёрстка перестаёт читаться без JS.** Шапка-консоль декоративна, и при проверке легко свалить начинку страницы в JS. Абзац, ссылки и проекты обязаны быть в HTML. Проверяется в Task 2.
5. **Печать визитки.** Тёмный фон на печати съедает тонер, а текст, нарисованный цветом, при выключенных фонах может стать белым на белом. Для визитки это реальный сценарий. Проверяется в Task 4.
6. **Состояние `auto` не выглядит как тёмная тема при светлой ОС.** Тёмная палитра живёт в `:root`, а `:root` без атрибута `data-theme` — это и есть «выбор не сделан». Если не описать светлую тему ещё и в `prefers-color-scheme`, режим auto перестанет означать «как в системе» и просто станет тёмным. Проверяется в Task 3.

```html
    var KEY = 'whlab-theme';
    var t = null;
    try { t = localStorage.getItem(KEY); } catch (e) {}
    if (t === 'light' || t === 'dark') {
      document.documentElement.setAttribute('data-theme', t);
    }
    var meta = document.querySelector('meta[name="theme-color"]');
    function paint(t) {
      if (meta) {
        meta.setAttribute('content',
          t === 'light' ? '#F4F7FA' : '#0A0F14');
      }
    }
    paint(t === 'light' ? 'light' : 'dark');
    window.whlabTheme = {
      get: function () { return t; },
      set: function (next) {
        t = next;
        if (next === null) {
          document.documentElement.removeAttribute('data-theme');
        } else {
          document.documentElement.setAttribute('data-theme', next);
        }
        try { localStorage.setItem(KEY, next); } catch (e) {}
        paint(next === 'light' ? 'light' : 'dark');
      },
      cycle: function () {
        this.set(t === 'dark' ? 'light' : t === 'light' ? null : 'dark');
      }
    };
  })();
</script>
```

Три состояния, а не два: `null` — авто, тему ОС решает CSS через `prefers-color-scheme`. Двух состояний не хватает, потому что пользователь, у которого тёмная ОС, обязан суметь получить светлую страницу и обратно.

- [ ] **Step 4: Добавить переключатель**

Кнопка в шапке, `type="button"`, подпись обновляется из `get()`. Событие — `click`, привязывается в конце `<body>`, чтобы не мешать разметке.
